# Vivo NFC Lab 0.3 — vivo X300 CN / OriginOS 7

Исследовательское Android-приложение на Kotlin **без root** для vivo X300 CN / OriginOS 7. Целевой профиль — **MIFARE Ultralight EV1 MF0UL21**: 41 страница по 4 байта, всего 164 байта.

> **Статус:** исходный проект, **не рабочая эмуляция** VIZIT. Стандартный Android HCE не эмулирует ISO 14443-3 Type 2 (MIFARE Ultralight). Для чтения Type 2 без root доступен публичный NFC reader API, но это **не даёт возможности отвечать считывателю в режиме карты**.

## Новое в v0.3: Shizuku без root

Системная диагностическая версия **использует официальный Shizuku API 13.1.5** и `ShizukuProvider` (не встроена Shizuku-программа). Поддержка самого Shizuku v13.6.0 зависит от прошивки и пользовательского запуска службы.

- Смотрит, запущен ли Shizuku и есть ли разрешение для Vivo NFC Lab.
- Показывает API-версию и UID процесса Shizuku (`2000` — shell, `0` — root).
- Вызывает системное окно разрешения Shizuku только по нажатию кнопки.
- По нажатию запускает **Shizuku UserService** — ограниченную read-only диагностику, выполняющую только фиксированные команды `service list`, `cmd -l`, `cmd nfc help`, `pm list packages` и фильтрующую вывод до имён NFC-служб / NFC-команд / пакетов.
- Не допускает пользовательские shell-команды, не запускает `dumpsys nfc` (в нём могут быть чувствительные сведения), не обращается к закрытой памяти Wallet, не меняет настройки, не пишет метки и не сохраняет дампы.
- Добавляет результат Shizuku-диагностики к безопасному отчёту.

**Схема работы на X300 CN:**

1. Установи Shizuku со [страницы релизов](https://github.com/RikkaApps/Shizuku/releases) или официального сайта. Для запуска без root включи *Для разработчиков* → *Беспроводная отладка*, затем выполни сопряжение внутри Shizuku с кодом из Android. В OriginOS возможны отличия меню.
2. В Shizuku нажми **Start / Запустить через беспроводную отладку** и проверь, что служба работает. После перезагрузки телефона обычно нужно запустить заново (в некоторых релизах есть автоматизация при доверенной Wi-Fi сети).
3. Открой Vivo NFC Lab 0.3 → **Проверить Shizuku** → **Запросить разрешение Shizuku** → разреши доступ в Shizuku.
4. Нажми **Системная NFC-диагностика (только чтение)**. Скопируй безопасный отчёт. Полный UID, дамп или пароли передавать не требуется.
5. На части прошивок команда `cmd nfc help` или список служб могут быть закрыты; пустой результат не означает отсутствия NFC.

**Ограничения:** Shizuku с ADB не предоставляет root, `com.vivo.wallet` может иметь другое фактическое имя пакета; наличие команд сервиса NFC не означает возможности эмулировать Ultralight (ISO 14443-3). Мы не знаем публичного импорта полного дампа Type 2 в vivo Wallet. **Не используем привилегии Shizuku для обхода защиты Wallet.**

## Возможности v0.2, сохранённые в v0.3

- Импорт собственного дампа MF0UL21 из Chameleon Ultra (`.bin`, ровно 164 байта), page-oriented `.eml`/`.hex` и Flipper Zero `.nfc` с полями `Page n:`.
- Сведения о системной роли `Wallet` в Android 15+ (если присутствует).
- Проверка числа экспортированных Activity/служб Wallet; **не** попытка использовать закрытые API.
- Сканирование оригинальной метки MF0UL21 и/или Chameleon Ultra через `NfcA`.
- Только MIFARE Ultralight EV1 **FAST_READ (0x3A)** страниц 0–40; никаких команд записи или изменения содержимого ключа.
- Полное чтение 41 страницы MF0UL21. Защищённая паролем память может вернуть ошибку чтения, которая показывается в отчёте.
- Сверка длины UID и полного UID **в памяти**, а также доступных страниц с импортированным дампом. UID и страницы в отчёт не попадают.
- Копирование отчёта и системная отправка отчёта; приложение не запрашивает интернет.
- Очистка ранее загруженного дампа при замене и при закрытии Activity.
- Отдельные JVM-тесты на чтение дампов и корректность сравнения.

## Что можно и нельзя выяснить

1. **Проверить:** телефон видит Ultralight (или совместимую Type 2 метку), может читать её страницы и сопоставить их с дампом.
2. **Проверить:** NFC-режимы, объявленные системой, наличие и версию `com.vivo.wallet`.
3. **Нельзя доказать:** что телефон способен воспроизвести Ultralight как карту. `NfcA.transceive()` используется **только в режиме чтения**, а не эмуляции.
4. **Пока нет подтверждения:** публичного API vivo Wallet для импорта всех страниц Ultralight или низкоуровневой Type 2 эмуляции через стороннее приложение. Факт `exported=true` у компонентов Wallet такого API не доказывает.
5. Сопоставление всех 41 страниц MF0UL21 не исключает проверку счётчиков, пароля, подписи, времени ответа и иной логики считывателя.

## Получить APK без Android Studio — GitHub Actions

1. Создай **закрытый** репозиторий GitHub (если хочешь, хотя в проекте нет секретов).
2. Распакуй ZIP, загрузи **содержимое папки VivoNfcLab**, включая скрытую папку `.github`, **в корень** репозитория.
3. Открой **Actions** → **Build diagnostic APK** → **Run workflow** (или отправь коммит в ветку `main`).
4. После успешной сборки открой запуск → **Artifacts** → `VivoNfcLab-debug-apk` → скачай `app-debug.apk`.
5. Перенеси APK на vivo X300 CN, разреши установку из выбранного приложения и установи его.

При желании можно собрать через Android Studio (JDK 17, SDK Platform 35; Gradle 8.11.1, Android Gradle Plugin 8.9.2, Kotlin 2.0.21). Проект **не содержит** Gradle Wrapper бинарник: CI самостоятельно устанавливает Gradle.

## Диагностический сценарий на vivo X300 CN

1. Включи NFC и (по желанию) запусти Shizuku по инструкции выше, затем открой Vivo NFC Lab.
2. **Обновить диагностику**. Убедись, что `NFC включён: да`.
3. **Открыть дамп** → выбери raw Chameleon Ultra `.bin` на 164 байта, page-oriented `.eml`/`.hex` на 41 страницу или Flipper `.nfc` с 41 строкой `Page n:`. Дамп Proxmark3 с заголовком напрямую не подходит: его нужно предварительно преобразовать в 164 байта page-data.
4. **Сканировать NFC-метку** → приложи **свой оригинальный ключ**, не снимая его раньше окончания чтения.
5. Посмотри `UID с дампом`, `Сравнено с дампом` и `Совпадает`. Несовпадения возможны из-за иного формата дампа или особенностей карты.
6. При желании проверь **Chameleon Ultra в режиме эмуляции** как отдельную метку для сравнения.
7. **Скопировать безопасный отчёт** → вставь его в чат, если хочешь продолжить исследование. **Сам дамп или полный UID отправлять не требуется.**
8. Кнопка **Открыть vivo Wallet** только запускает родной Wallet; ничего не импортирует автоматически.

## Приватность и безопасность

- Исходный код не использует `android.permission.INTERNET`.
- Полный дамп не записывается в файлы приложения, а сравнивается в памяти. В системном выборе файла или во временной памяти ОС могут оставаться обычные следы работы Android.
- Отчёт показывает метаданные, число страниц, результат сравнения, ATQA/SAK, версию Wallet; в отчёте **нет полного UID и содержимого страниц**. Имя выбранного файла видно только на экране импорта.
- Никаких попыток обойти подпись, sandbox или привилегии системного Wallet, подменить его APK или открыть закрытые службы.
- Используй только со своими ключами и с разрешения администратора системы доступа.

## Проверки исходников

Pure Kotlin JVM-тесты включают проверку raw MF0UL21 BIN на 164 байта и Flipper `.nfc` с 41 страницей. Для кода Shizuku UserService нужна настоящая сборка Android SDK; статическая проверка исходников не заменяет компиляцию APK. Это **не** проверка на реальном vivo X300 CN. ## Источники и документация

- [Android HCE](https://developer.android.com/develop/connectivity/nfc/hce) — эмуляция ISO-DEP/APDU, не MIFARE Ultralight.
- [Android MifareUltralight](https://developer.android.com/reference/android/nfc/tech/MifareUltralight) — чтение страниц (не эмуляция).
- [Android NfcA](https://developer.android.com/reference/android/nfc/tech/NfcA) — интерфейс чтения/трансивера в reader mode.
- [FAQ vivo Wallet о домофонных картах](https://bbs.vivo.com.cn/newbbs/thread/33160871) — штатное копирование UID не гарантирует совместимость с любым считывателем.

## План после реального отчёта

- Уточнить точное имя и версию vivo Wallet, доступные системные роли и NFC-режимы конкретного X300.
- Если Vivo предоставляет официальную функцию добавления такого типа карты, интегрироваться через **документированный** путь.
- Если полного Type 2 provisioning/API эмуляции в прошивке нет — не обещать поддержку Ultralight без root; предложить подтверждённые варианты.

- [Shizuku-API](https://github.com/RikkaApps/Shizuku-API) — API, `ShizukuProvider`, permissions, `UserService`.
- [Shizuku user manual](https://shizuku.rikka.app/guide/setup/) — запуск через беспроводную отладку.
